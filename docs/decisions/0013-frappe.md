# ADR 0013: Frappé is the CLI: one command table drives it, every command is one stateless process, and `frappe check` reports in MRDP or terminal typography

Date: 2026-09-27

Status: accepted.

## Context

The CLI must serve humans and agents: a fast Tier-1 type-check loop, diagnostics in two modes (ANSI for humans, MRDP for agents), and exit code 1 for invalid input. Crystal cannot run an application without building it natively. The CLI also talks to Latte's daemon for service and database side effects.

## Decision

The commands and what they print are stated on the website ([site.html](../../website/source/site.html)), chiefly its Commands reference and its guide for agents, in the sections cited below by anchor, and in the doc comments under [src/frappe](../../src/frappe). This record states what was chosen.

1. **The binary is `frappe`.** `caramel` names the framework shard that applications depend on. Every command, with its syntax, is listed in `site#c-commands-frappe`.
2. **One command table states the command line.** `Commands::TABLE` in [src/frappe/commands.cr](../../src/frappe/commands.cr) is the single source for help, family help, completion, argument validation, pinned-release dispatch and `frappe agent-manifest` (`Commands`). Each command carries a one-line `brief` and `examples`. `spec/frappe/commands_spec.cr` fails when an example does not parse as its command, when a command's first word is in no help group or in two (`GROUPS`), or when a run of words that two or more commands share has no line in `FAMILIES`.
3. **Help and completion are generated from the table.** `frappe help` prints the commands in groups, one short line for each command or family of subcommands (`db`, `make`). `frappe help WORDS` and `frappe WORDS --help` print the same page: a command's description, usage and examples, or a family's subcommands. Headings are uppercase and bold only on a terminal without `NO_COLOR` and with `TERM` not `dumb`; lines are at most 80 columns (`Help`, `Terminal.color?`). `frappe completion zsh|bash|fish` prints a completion script generated from the table (`Completion`). The commands are in `site#c-commands-frappe`.
4. **A usage error exits 1 with the command's syntax.** Unknown commands and malformed arguments exit **1** with the command's exact one-line syntax and a "Did you mean" suggestion (`site#c-commands-output`). A family run without a subcommand, or with an unknown one, prints its subcommands to standard error on a terminal and exits **1**. Piped or with `--agent`, it prints the unchanged MRDP `USAGE` block.
5. **Commands are stateless.** Every Frappé command is a one-shot process with no session state. Latte's daemon is a service supervisor ([ADR 0012](0012-latte.md)), not a JSON-RPC agent protocol. Frappé calls it only to start services, provision sites, branches and test databases, and register upstreams.
6. **`frappe check` is Tier 1.** It runs `crystal build --no-codegen` for the project's main target with the development flags, parses the real compiler output (`Check`, `Diagnostics`), and classifies each diagnostic as one of the eight codes that `site#c-agents-diagnose` lists for `check`. The compiler types a method body only when something references it, so a library whose declarations are mostly uncalled makes its boot reference them (as the boot of [ADR 0030](sweettalk/0030-scope-and-modules.md) does).
7. **Diagnostics have two modes, chosen by where stdout goes.** Mode A (a TTY, or `--human`) draws a box: file and line, the source line, a caret, the message and a Remediation block (`Diagnostic#render`). It is coloured only on a TTY, never with `NO_COLOR` set or `TERM=dumb`. Mode B (`--agent`, or stdout not a TTY) prints MRDP (`MRDP.agent?`). The grammar is `ERR <CODE>[:<status>] at <file>:<line>:<col>`, then `NODE`, `MISSING`, `MSG`, `FIX`, `PATCH: INSERT "…" AT|AFTER <line>:<col>`, `SYNTAX`, `SUGGEST`, `OK <command> <summary>`, and exit 0 exactly when there is no `ERR`. Usage errors, migration lint refusals (`LINT_<RULE>`) and `db diff` halts (`DIFF_HALT`) use the same MRDP. `frappe agent-manifest` ends with the grammar (`site#c-agents-diagnose`).
8. **A diagnostic names its repair as a `PATCH` where one is mechanical.** For a contract mismatch, the router reports `Contract: file:line:col` from a compile-time `CARAMEL_CONTRACT_LOCATION` (`Caramel::Action.contract`); `ERR` points at the action's `contract do`, and `PATCH` inserts the missing field on the next line. `N_PLUS_ONE` patches insert `.preload(:name)` after the query. `NULLABLE_WHERE` reads the rule and the fix from SugarORM's `MayBeNil` type and drops the compiler's own suggestion (`Diagnostics.nullable_where`). Worked examples are in `site#c-agents-diagnose`.
9. **Tier 2 is a native build.** Native builds serve the running application: `frappe dev`, `routes`, `migrate`, `seed`, `corretto` and `db diff`'s headless `schema` binary (`site#c-commands-app`). Crystal's interpreter does not serve them. Deployment builds are outside this record: the release build is in [ADR 0032](0032-production.md). Tier 1 remains the agent's verification loop.
10. **Commands share the development build.** A command reuses a build of the same inputs: the source signature `frappe dev` hashes, the toolchain, the framework version and the development flags. It takes `frappe dev`'s build, hard-linked into `.caramel/application` so the session's cleanup cannot delete it, or else the previous command's, and builds into `.caramel/application` only when neither matches. `.caramel/build.lock` serializes the application's builds: a command waits while `frappe dev` or another command builds, and `frappe dev` waits for a command's build (`Tools#compile`, `BuildSlot`, `BuildLock`).
11. **A command may ask the compiled application for its answer.** Such a command is a row of the same table. Frappé takes the shared development build, runs one of the binary's own commands, and prints what it answers or renders the document it returns. The binary's command is built in, as `routes` and `schema` are, or one a library registers through `Caramel::Crema.command` ([ADR 0027](0027-crema.md)). A binary that lacks the command answers with its usage and status 2, and Frappé then says what the application does not require. `frappe routes` runs the binary's `routes` this way (`site#c-commands-app`). So do three rows of the table that print what a domain declares: `frappe glossary [--json]` and `frappe contexts [--mermaid]` ([ADR 0036](sweettalk/0036-strategic-design.md)), and `frappe requirements [ID]` ([ADR 0035](sweettalk/0035-reads-and-rules.md)).
12. **`frappe expand FILE:LINE:COL` prints the plain Crystal that a macro call expands to.** A macro call written inside another macro's block, such as `field` inside `contract do … end`, is never expanded itself. `frappe expand` then tries the calls whose blocks enclose the position, innermost first, prints the first that expands with the steps up to the one that expands the requested call, and names that call (`ExpandFallback`). A position on a call that no enclosing call expands exits 1, naming the enclosing calls it tried.
13. **`frappe words [WORD] [--json]` prints a vocabulary from the macros that define it.** It works outside an application. Each macro, and each method an author calls as a word, carries a block of tags in its doc comment, and Frappé reads the block and the macro's parameters with Crystal's parser, from the sources of its own release (`Words`; the tags are in `WordDoc`). A refusing macro, whose body only raises, has none. No word is listed apart from its macro: `spec/frappe/words_spec.cr`, the check lane that compiles every example and `scripts/check website` fail when the macros, their tags, the guide or the skill disagree (`WordDrift`). An unknown WORD exits 1 naming the nearest words. The vocabulary it prints is that of [ADR 0030](sweettalk/0030-scope-and-modules.md).

## Reasons

- Naming the CLI after its product (Frappé is the CLI) avoids renaming a shipped binary that every script and template already uses.
- A single table cannot drift from help, validation or the manifest. An agent that reads the manifest gets exactly what the parser accepts.
- PATCH lines that apply mechanically turn a compile error into a one-step repair for an agent.
- The compiler's own suggestion for a nullable `where` names the sentinel, not the query, so the diagnostic leaves it out.
- Rejected: Crystal's interpreter for Tier 2, because it is missing from the official macOS build and, where present, is slower than a warm build and fails under a request loop. The official macOS build that the managed toolchain installs is compiled without it, and the experimental interpreter in other builds started a 22-resource application more slowly than a warm build and failed under a request loop ([measurements](https://github.com/caramelizedev/caramel-notes/blob/main/research/local-performance.md#follow-up-compiler-side-options-2026-10-02)).
- One lock for all of an application's builds means no two builds write the program's compiler cache at once. A hard link keeps a command's build when the `frappe dev` session that made it cleans up.
- A vocabulary reference kept beside the macros, in the guide or the skill, drifts from them. Reading the parameters and the doc comment of the macro itself leaves one place to edit and a check that fails when it is not edited.
- Rejected: a list of words in Frappé, which would be a second copy of what each macro states; and generating the guide's tables from the macros, because the guide teaches and the reference lists.
