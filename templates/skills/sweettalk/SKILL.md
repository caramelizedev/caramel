# SweetTalk in this application

shard.lock pins this application's Caramel release. Its SweetTalk guide, in Markdown, is
https://caramelize.dev/docs/VERSION/sweettalk/index.md, with VERSION from shard.lock. Each
line below ends with the section that states it; where they differ, the guide is right.

Read first the map of Domain-Driven Design patterns to SweetTalk words:
https://caramelize.dev/docs/VERSION/sweettalk/index.md#c-sweettalk-ddd

Before you guess a word's options, run `frappe words WORD`: it prints the usage, each option and
an example that compiles, read from the macros of this release, and `frappe words` lists them.
https://caramelize.dev/docs/VERSION/sweettalk/index.md#c-sweettalk-words

## Rules agents most often break

- Give every context, kernel, value, aggregate, entity, event, projection, specification, service, unit, calculation and process `means:`. https://caramelize.dev/docs/VERSION/sweettalk/index.md#c-sweettalk-meaning
- Name another context's types (`Other::`) or call its services (`Other.price_of`) only in a context that says `follows: Other`, or inside its `border Other`. A `follows: Other` or `shares: Money` that the context never names fails compilation: remove it. https://caramelize.dev/docs/VERSION/sweettalk/index.md#c-sweettalk-contexts
- Give a context that outgrows a file a directory: keep `context Name, …` with its options, the values the whole context uses and `publishes` in `<domain>/<name>.cr`, put each aggregate with its values, events, queries and specifications in `<domain>/<name>/<aggregate>.cr` inside `within Name do … end`, and require the files from the domain file in the order their names are used. https://caramelize.dev/docs/VERSION/sweettalk/index.md#c-sweettalk-files
- Once a context `publishes`, name and call only what it publishes. https://caramelize.dev/docs/VERSION/sweettalk/index.md#c-sweettalk-published
- Name a kernel's types, commands and events (`Money::Cents`) only in a context or kernel that says `shares: Money` and that the kernel's `shared_by:` lists. A kernel holds only values and aggregates, names no context, shares only kernels declared before it, and holds only what two or more of its sharers name. https://caramelize.dev/docs/VERSION/sweettalk/index.md#c-sweettalk-kernel
- Name `Caramel::Outbound` or `HTTP::Client` only inside `border Name, outside: "…"`, call it from a `whenever`, and fake it in specs with `Corretto.stub_wire`. https://caramelize.dev/docs/VERSION/sweettalk/index.md#c-sweettalk-outside
- `subdomain: :core`, `:supporting` or `:generic` labels a context for readers and changes no rule. https://caramelize.dev/docs/VERSION/sweettalk/index.md#c-sweettalk-subdomains
- Change one aggregate per command, service, policy or process step, by as many commands as it needs. For work across aggregates, write a `process`, or emit an event and react to it with `whenever`; two commands inside one `SugarORM::Repo.transaction` commit and roll back together. https://caramelize.dev/docs/VERSION/sweettalk/index.md#c-sweettalk-ddd
- When two aggregates must change together, declare a `unit` in the context: `changes:` lists the aggregates its commands change, `locks:` the arguments whose rows it locks first, in table then id order, and a `never` in its body is a rule over the set. Call it from an action, a service or a handler, never from a command; a command on a type outside `changes:`, or on an existing row `locks:` did not name, raises `SweetTalk::Boundary`. A unit a client may submit twice takes `once_by: key, otherwise: "…"` and runs once per key. https://caramelize.dev/docs/VERSION/sweettalk/index.md#c-sweettalk-units
- A split, a rounding or a conversion that changes nothing is a `calculation share(total : Cents, parts : Int32), returns: Array(Cents), means: "…" do … end` in the context, with its identity as an `always` on `result` in the body. It takes values and ids, never aggregates, and its body never finds, emits or calls a service or a unit; it refuses an input outside its domain with `SweetTalk::Refusal`, and a broken rule raises `SweetTalk::Broken`, a defect. https://caramelize.dev/docs/VERSION/sweettalk/index.md#c-sweettalk-calculations
- Change state only in the aggregate's commands (`to`), never through `Rows`. `has tea : Catalogue::Tea` stores an id: load the aggregate with `find` when you need it. Build an entity by name, `Line.new(tea: tea, quantity: quantity)`, so a defaulted attribute may sit anywhere; `created_at` and `updated_at` read the row. An entity may hold entities of its own, at any depth. `has flag : Bool` reads as `flag?` too, so no `moves` state shares its name. A projection or process attribute other than the key is optional or defaults to a literal or a value built from one, as in `Cents.new(0)`. https://caramelize.dev/docs/VERSION/sweettalk/index.md#c-sweettalk-aggregates
- An aggregate or an entity is keyed by a UUID it gets when it is built, so `id` works before `create`; take an id from the aggregate, a contract field or a stored fact, never from a number such as `Order::Id.new(1)`. Write `ids Int64` before the first context only when the domain's tables already have Int64 keys; a tenanted domain's ids follow its tenant's key type. https://caramelize.dev/docs/VERSION/sweettalk/index.md#c-sweettalk-aggregates
- Let the database keep what must hold whoever writes the row: `has label : String, unique: true` or `unique: "sentence"`, `index: true`, `check: {"sql", "sentence"}`, and over several attributes `unique :a, :b, otherwise: "…"`, `index :a, :state` and `check :name, "sql", otherwise: "…"`. A violation is a `Refusal` with that sentence. An entity's `unique` is unique within its aggregate; a projection or process declares none. Before migrating a `unique` onto rows, find the duplicates with `GROUP BY … HAVING count(*) > 1`. https://caramelize.dev/docs/VERSION/sweettalk/index.md#c-sweettalk-aggregates
- Say an optional part with `?` only for what may be absent; a rule tying attributes is a `never`. Set a reference with `self.owner = other`. `one_of: %w[…]` is a closed list, and `value Day, Date` a calendar day kept in a `date` column: pass the day in, there is no `Day.today`. https://caramelize.dev/docs/VERSION/sweettalk/index.md#c-sweettalk-richer-values
- Attributes only some members of a closed set hold are optional and listed per member: `has kind : Kind, parts: {payment: [payee], net_settlement: [payee, leg]}`. The database and a `never` keep each member to its parts, and `settlement.as_payment` reads them. https://caramelize.dev/docs/VERSION/sweettalk/index.md#c-sweettalk-aggregates
- A rate or an amount with decimals is `value Rate, Decimal(20, 8), at_least: "0"`, exact in a `numeric` column, after `require "caramel/sweet_talk/decimal"`; its bounds are decimal text and its JSON is a string. A document is `value Evidence, Json(Snapshot)` or `Json`, a `jsonb` column asked only for equality or absence, never sorted. https://caramelize.dev/docs/VERSION/sweettalk/index.md#c-sweettalk-values
- Money in a currency is `require "caramel/sweet_talk/money"` with `currencies %w[USD EUR]` in a kernel: `has original : Money::Amount` keeps the currency beside the minor units, two amounts combine only through `Money.same(a, b) { |x, y| x + y }` or `Money.by_currency`, text with too many decimals is refused (`round(text, rounding:)` on purpose), and `quote Rate` with `amount.convert(rate)` converts exactly; never use `Float64` for money. https://caramelize.dev/docs/VERSION/sweettalk/index.md#c-sweettalk-money
- Share an amount by weights with `allocation split, of: Money::Amount, by: Weight, remainder: :largest_fraction, means: "…"`, never by hand: `Ledger.split(total, weights)` gives each key the floor of its share and the units left to the largest fractions, ties to the smaller key (`:first`, `:last` or `:to` send them to one key), and its rules say the parts add up to the total; run them with `Corretto.property(Ledger.split)`. https://caramelize.dev/docs/VERSION/sweettalk/index.md#c-sweettalk-money
- Emit only the aggregate's own events, `carries: [kind]` for fields it holds. For a change no aggregate holds, declare the context's own `event` (no `carries:`) and `emit` it from a service body, nowhere else. A handler reads the event's fields, which are facts as emitted, not the aggregate now. https://caramelize.dev/docs/VERSION/sweettalk/index.md#c-sweettalk-events
- A policy runs as a job after the command commits; jobs start in declaration order (policies, then projections, then processes) and finish in any, so read the event, not another handler's row; a handler that must see another's row saved says `whenever Event, after: Owner`, and that owner's job enqueues it. Set a flaky handler's retries with `attempts:`, `backoff:` and `base:` on its `whenever`. In a spec, read what a command emitted with `SweetTalk.emitted { … }`. https://caramelize.dev/docs/VERSION/sweettalk/index.md#c-sweettalk-events
- `context X, event_log: true` keeps every event in `x_events`, in the command's transaction; `event_log: 90.days` keeps each that many days and prunes on Cold Brew's schedule. Read it with `X.logged(Event, subject:, since:, before:)`, read what an event led to with `X.reached(event)`, and rebuild a projection from a log that keeps every event with `SweetTalk.rebuild(X::Projection)`, which leaves an event a queued job still has to apply to that job. Give a field added to a stored event `older: {field: value}`. https://caramelize.dev/docs/VERSION/sweettalk/index.md#c-sweettalk-event-log
- Keep what is in effect after a correction on the aggregate, set by the command that finalises it; never scan corrections for it. Read what was known at a moment with `X.logged(subject: id, before: moment)`. https://caramelize.dev/docs/VERSION/sweettalk/index.md#c-sweettalk-known-at
- Stop a command with `refuse "message"`. State invariants with `never` and `always`, on the entity when the rule is the entity's, and move the lifecycle with its movers, such as `placed!`. `create` announces `Created`, carrying every attribute; declare `event Created, carries: [member], means: "…"` to carry fewer. https://caramelize.dev/docs/VERSION/sweettalk/index.md#c-sweettalk-commands
- A record that must keep what a referenced aggregate said when it applied pins it: `has rules : Setup::Rules, pinned_at: :finalized` copies it in the move into that state, and `pinned_rules` reads the copy, which no command changes. https://caramelize.dev/docs/VERSION/sweettalk/index.md#c-sweettalk-lifecycle
- Use a `factory` when an aggregate must start with arguments or an event of its own; declaring it removes `create` and its `Created`, so replace each `create` call with the factory in the same change. https://caramelize.dev/docs/VERSION/sweettalk/index.md#c-sweettalk-factories
- Read with `find`, `find?`, `all`, and the `finds` and `counts` an aggregate, a projection or a process declares; sort and limit with `order:` and `first:`. A `finds` block is only for what `where:` cannot say. Prefer `sums spent_by(member : Account), of: Line.price, where: {…}` for a total and `groups …, of:, by:` for totals by one key, declared beside them: one statement over the bound tenant's live rows. Use `SugarORM.sql` only for what they cannot state, such as an average, a `Float64` or `Time` key or several keys, outside the context and with the tenant predicate written out. `find(id, entities: false)` reads the root alone when a request only checks it; its lists raise, and a command on it loads them. https://caramelize.dev/docs/VERSION/sweettalk/index.md#c-sweettalk-queries
- State a rule once with `specification`, then use `name?` in guards and `satisfying:` in queries. https://caramelize.dev/docs/VERSION/sweettalk/index.md#c-sweettalk-specifications
- Read the domain before changing it: `frappe glossary` prints every term with its meaning, a value's bounds, an aggregate's moves, an event's handlers in the order they run and a unit's `changes:` and `locks:`; `frappe contexts` prints the context map. https://caramelize.dev/docs/VERSION/sweettalk/index.md#c-sweettalk-glossary
- When the team numbers its requirements, list them once with `requirements "AC-01", "AC-02"` before the first context, add `assures: "AC-01"` to the rule that answers each, and write the id in an example's name; `frappe requirements` lists each id with what assures it. https://caramelize.dev/docs/VERSION/sweettalk/index.md#c-sweettalk-requirements
- Rename with `renamed_from:`, so tables, channels and queued jobs keep their stored names. https://caramelize.dev/docs/VERSION/sweettalk/index.md#c-sweettalk-renames
- In a multi-tenant application, name the `tenant` before the first context, and mark a context `central: true` only when every tenant shares it. https://caramelize.dev/docs/VERSION/sweettalk/index.md#c-sweettalk-tenancy
- After changing what the domain stores, run `frappe db diff`, then `frappe migrate`; a row breaking a new CHECK, key or unique index stops it. https://caramelize.dev/docs/VERSION/sweettalk/index.md#c-sweettalk-aggregates
- A contract field may be a value or an aggregate's id: it binds from the type the value wraps, and its refusal is the field's error. A value with parts is one field per part. A refusal `handle` does not rescue answers 422, and `SweetTalk::Missing` answers 404; override `render_refusal` to answer otherwise. https://caramelize.dev/docs/VERSION/sweettalk/index.md#c-sweettalk-actions
- On a screen, never compare a closed-set value's or a state's text or branch on it with `else`: write `case kind.member in .receipt? … end` naming every member, give each member a catalog message in that `case`, and offer commands by mapping each state of `Order.moves_from(order.state)` in a `case … in`. Give a refusal about one input `on: :field` (`refuse "…", on: :tins`), so the action answers it under that field. https://caramelize.dev/docs/VERSION/sweettalk/index.md#c-sweettalk-screens
- To show what a change would record before it records it, run the body in `SweetTalk.preview { … }`, carry `preview.fingerprint` in a hidden field typed `SweetTalk::Fingerprint`, and commit with `SweetTalk.commit(contract.expected) { … }` around the same body; it raises `SweetTalk::Stale`, answered 422, with the fresh preview when the outcome changed. Never keep a second preview path. A screen that refreshes as a person types never previews: it loads with `find` and calls the calculation the unit's body calls. A preview lists a unit's failing `never` and `always` lines under `preview.blockers`, beside the events and changes, and `preview.value` is what the block returned. A unit's `warn "…" { … }` refuses a plain call and is confirmed by the fingerprint. A command, factory or unit never names an outside border's module. https://caramelize.dev/docs/VERSION/sweettalk/index.md#c-sweettalk-preview
