# ADR 0024: Internationalization is built in, entered through one require, with catalogs written as Crystal literals and checked by the compiler

Date: 2026-10-02

Status: accepted.

## Context

Internationalization is built in. An application that never opts in pays nothing: no per-request work, no allocation, no added binary code and no extra compile step.

## Decision

The rules an application relies on are stated on the website ([site.html](../../website/source/site.html)), chiefly its Internationalization guide, in the sections cited below by anchor, and in the doc comments of [src/caramel/i18n.cr](../../src/caramel/i18n.cr), [src/caramel/i18n](../../src/caramel/i18n), [src/caramel/wording.cr](../../src/caramel/wording.cr) and [src/sugar_orm/wording.cr](../../src/sugar_orm/wording.cr). This record states what was chosen.

1. **Core holds hooks with English and identity defaults.** Every framework message comes from a method of `Caramel::Wording` or `SugarORM::Wording` that returns the English text, including the body of `Caramel::Router.not_found` and the default message of `Action#not_found`. The expired-form text is `Caramel::Wording.expired_form`; there is no `Caramel::Application::EXPIRED_FORM` constant. `Caramel.language` returns `"en"`, and `Caramel.localize_path` returns its path unchanged; resource path helpers pass through it (`resource_paths`). `Application#handle` routes through `localized`, which only yields, and `#call` streams through `streaming`, which only yields. `CommandLine.translations` prints that no locales are declared.
2. **`require "caramel/i18n"` is the only way in.** `src/caramel.cr` does not require it. It redefines the hooks that core holds. A `macro finished` guard in `Caramel::I18n` refuses a program that requires it without calling `Caramel.locales` (`site#c-i18n-enable`).
3. **A catalog is a Crystal literal that the compiler checks.** Catalogs live in `app/locales/CODE.cr`, with no `{{ run }}` helper and no build step. `Caramel.locale` records one and `Caramel.locales(default:, prefix: false)` checks them all and writes the code; their doc comments and `site#c-i18n-catalogs` state what a code, a value, a key and a placeholder are, and `I18n::KEY`, `I18n::RESERVED_KEYS` and `I18n::KEY_ONLY_RESERVED` hold the names refused. A literal `%{` cannot be written. Every mistake is a compile error at the offending catalog value, with a fixed problem text and a remediation. `site#c-i18n-refusals` lists them; beyond that list, these also fail compilation: an invalid locale code, a duplicate locale, a plural form the language does not use, an unknown framework key, and a missing or unknown default.
4. **A locale may omit keys, and never adds one.** A missing key uses the default locale's text, and `translations` lists it. A key a locale defines must exist in the default locale, with the same kind of value and the same placeholders (`Caramel.locales`, `site#c-i18n-refusals`).
5. **`Caramel.locales` writes an enum, typed messages and the hooks' redefinitions.** `Caramel::Locale` is an enum of the declared locales that answers each one's code, name, direction, plural category and formatting data. `Caramel::Messages`, which `t` returns, is a struct per catalog group with one typed method per message (`I18n.__messages`, `site#c-i18n-messages`). Every framework message some catalog translates is redefined with the hook's signature; it answers the request locale's text, else the default locale's, else the English one through `previous_def` (`I18n.__wording`).
6. **The reserved `caramel:` section carries formatting data and the framework's messages.** It takes only the keys of five groups: `language`, `number`, `time`, `errors` and `pages`. Every key is listed in one place, the section "Look up catalog keys" of the website's Internationalization guide (`site#c-i18n-reference`): the formatting keys with their meaning, and every `errors` and `pages` key with its English text and placeholders. In source the same keys are `I18n::FRAMEWORK_MESSAGES`, `I18n::FRAMEWORK_TEXTS` and `I18n::TIME_LISTS` in [catalog.cr](../../src/caramel/i18n/catalog.cr). `errors.key_kept` is the error of an update that changes a record's id ([ADR 0007](0007-sugarorm.md)). That section also states the directives a time pattern may use (`I18n::DIRECTIVES`) and the fallback order. English supplies the language name `English`, the English month and day names and their three-letter abbreviations, `AM` and `PM`, and the formats `date` `%B %-d, %Y`, `time` `%-I:%M %p`, `datetime` `%B %-d, %Y %-I:%M %p` and `short_date` `%b %-d` (`I18n::ENGLISH`). Only the default locale adds format names (`site#c-i18n-formats`).
7. **Plural rules are CLDR 47's cardinal rules for whole numbers.** There is one method per family of languages (`I18n::Rules`). `I18n::FAMILIES` states which categories a plural message must and may define, and `site#c-i18n-reference` lists the languages with built-in rules, how a tag with a region or script finds them, and `plural:` for any other language. `Locale#dir` is `rtl` for the languages of `I18n::RIGHT_TO_LEFT` and `ltr` for every other.
8. **A message is plain text unless it is given safe HTML.** A message with placeholders is built by `Caramel::I18n.compose`, whose doc comment and `site#c-security-escaping` state when the result is safe HTML and what is escaped.
9. **The request's locale is resolved around routing and bound to the fiber.** `Application#localized` resolves it: a `locale` parameter on a GET or HEAD that names a declared locale is answered without routing; otherwise the locale is the prefix's, else the cookie's, else the best `Accept-Language` match, else the default. The prefix, the switch's answers, the cookie and the `Accept-Language` limits are in `site#c-i18n-language`, and the match order in `I18n.negotiate`. Routing and streamed bodies run inside `Caramel::I18n.with`. Every response says `Content-Language`; a negotiated one adds `Vary: Accept-Language, Cookie`. A prefix locale that differs from the cookie updates it. `handle` secures every response the hook returns, the switch's redirect included.
10. **Framework messages render when they are created.** Errors keep their `Hash(String, Array(String))` shape, and JSON clients receive localized text (`site#c-i18n-errors`). A message created outside a request, `spawn`ed fibers and Cold Brew jobs use the default locale unless wrapped in `Caramel::I18n.with`; how a job carries its locale is in `site#c-i18n-jobs`.
11. **Frappé turns internationalization on, and generated applications start in plain English.** `frappe make locale CODE` writes the catalogs and the i18n lines in `config/application.cr`; after it, `frappe make resource` writes `t.` calls and inserts the resource's messages into the default locale's catalog (`site#c-i18n-enable`, `site#c-commands-frappe`), among them `in_use`, the text of the generated Destroy's 409 ([ADR 0052](0052-sugarorm-conflicts-and-reads.md)). It refuses a field or plural that would be an invalid catalog key. `frappe translations` runs the application's `translations` command (`site#c-i18n-check`).

## Reasons

- Catalogs as Crystal literals and typed message methods make every catalog mistake a compile error on the catalog's line; unused messages add nothing to the binary.
- Hooks that one opt-in require replaces keep a plain application unchanged and free of i18n code.
- A plural is a named tuple whose keys are all CLDR categories or `=N`, so a group's keys cannot all be category names.
- Each message is a method, so its key cannot be a Crystal keyword or a method every value has. A placeholder is a keyword argument, so it may be named `finalize`, which a key may not.
- Rendering at creation keeps the error hash and JSON shape clients read.
- Escaping by default, a per-request locale and localized form URLs avoid injection, races and POST-to-GET redirects. Resource path helpers pass through `Caramel.localize_path`, so with `prefix: true` generated links and forms carry the prefix.
- Falling back to the default locale and reporting gaps never blocks shipping.
- Rejected: YAML catalogs through a `{{ run }}` macro, because they add a compile step and move errors off the catalog's line.
- Rejected: Frappé-generated code, because it drifts.
- Rejected: bundled CLDR formatting data, because it enlarges every localized binary.
- Rejected: i18n-ready applications from day one, because all would pay.
