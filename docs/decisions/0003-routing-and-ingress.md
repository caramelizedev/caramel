# ADR 0003: Routes are verified against typed contracts at compile time, and each route declares how its request is read

Date: 2026-09-27

Status: accepted.

## Context

Crystal's `TypeNode#instance_vars` is available only to macros expanded inside methods, so a top-level `Router.draw` block cannot read a contract's fields through it. The router still has to verify every route against its action's contract at compile time, and match requests without allocating.

Reading every request the same way before routing, and checking CSRF on every POST, PUT, PATCH and DELETE, does not fit two kinds of client:

- **JSON clients** ([#2](https://github.com/caramelizedev/caramel/issues/2)) need their body parsed into contract fields without changing form parsing for the whole application.
- **Signed webhooks** ([#3](https://github.com/caramelizedev/caramel/issues/3)) and token-authenticated APIs need the exact bytes (for an HMAC), a limit of their own, and an authentication policy in place of the browser CSRF check.

A contract field that takes only the built-in types makes an action read an `Int32` and build its own type from it in `handle`, where a failure names no field.

## Decision

The rules an application relies on are stated on the website ([site.html](../../website/source/site.html)), chiefly its Routes and contracts and Security defaults references, in the sections cited below by anchor, and in the doc comments under [src/caramel/http](../../src/caramel/http), [src/caramel/contracts](../../src/caramel/contracts) and [src/caramel/action.cr](../../src/caramel/action.cr). This record states what was chosen.

1. **Every action declares a typed contract, and its fields are compile-time constants.** An action declares `contract do … end` with lines of the form `field name : Type, min:, max:, default:`. A field takes `String`, `Int32`, `Int64`, `UUID`, `Float64`, `Bool`, `Time`, `Caramel::UploadedFile`, a field value, or a bounded `Array(T)` of one of the first seven or of a field value; what each accepts, the bounds and the declarations that fail compilation are in `site#c-routing-contract`. Each `field` records a `CARAMEL_FIELD_<NAME>` constant holding the name, the scalar type, nilability, whether a default exists, a summary and the declared type.
2. **`Router.draw` verifies every route against those constants.** All routes live in one `Caramel::Router.draw` block, which reads each action's `CARAMEL_FIELD_<NAME>` constants. A route fails to compile when its action is undefined, does not inherit from `Caramel::Action` or has no contract, and when it binds a `:param` to a field that is missing, nilable, defaulted, or not bound from `String`, `Int32`, `Int64` or `UUID`; an `Array` field cannot bind a route parameter. Each error names the route's source location and gives a one-line remedy. The full table of refusals is in `site#c-routing-checks`.
3. **Contracts are parsed, never hydrated.** `Contract.parse(input)` binds each field by name from, in order, the route parameters, the body and the query. It collects every error. A name sent twice is an error, except for an `Array` field, which takes each occurrence in order. The router calls `handle` only with a valid contract. Sources, messages and the 422 answer are in `site#c-routing-binding` and `site#c-routing-errors`, and on `RequestContract`.
4. **Any type binds as a field through a protocol in core.** A type that includes `Caramel::FieldValue(W)` and defines `self.from_field(raw : W, & : String ->)` binds like a field of `W`; the types `W` may be and what `from_field` returns are on `FieldValue` and in `site#c-routing-contract`. The JSON type, the text grammar and the "must be a valid" error are `W`'s. Such a field may be nilable, take `default:` and be an `Array` item. It binds a route parameter when `W` is `String`, `Int32`, `Int64` or `UUID`, and takes no `min:` or `max:`. Its summary names both types, as in `quantity:Ordering::Quantity(Int32)` (`site#c-routing-tools`). Core names no type that uses the protocol; [ADR 0033](sweettalk/0033-framework-boundary.md) records one user.
5. **One UUID spelling binds.** A contract field or route parameter of type `UUID` binds from the canonical lowercase hyphenated form only (`RequestContract::CANONICAL_UUID`). Other text is a field error, and a route parameter that does not bind answers 404. `min:` and `max:` on a `UUID` fail compilation. `<singular>_path(id : UUID)` builds a resource path from a UUID (`site#c-routing-paths`).
6. **Matching walks a segment trie built at boot and allocates nothing.** `draw` generates an `AppRouter` that holds the verified route table, with one generated method per route and a `case` that selects among them. At boot a segment trie is built once from that table; static children win over the parameter child, and matching backtracks (`Router::Tree`, `site#c-routing-matching`). Matching walks byte offsets in a stack-allocated `Segments` value and uses no regular expressions. Binding allocates only the decoded parameter strings, the input maps and the contract.
7. **An action declares how its route reads the request.** An action may declare `ingress body:, limit:, csrf:, authenticate:, open:` beside its contract; each keyword is optional, and a route without a declaration reads with `Ingress::DEFAULT`. What each keyword does, the limit's range and default, and how a subtype inherits and replaces its parent's ingress are on the `ingress` macro of `Caramel::Action` and in `site#c-security-ingress`. Everything is checked at compile time. Beside the refusals those two homes state (`csrf: false` without `authenticate:`, a redeclaration that drops the parent's authenticator, `open: true` beside `authenticate:` or under an authenticating parent, a form declaration under a raw parent), the macro refuses unknown or positional keywords, non-literal values, a limit out of range, a second declaration in one type, `raw_body` on a form action, and an authenticator that does not exist, does not return `Bool`, or is a keyword or a reserved name. `routes` and `frappe routes` print a route's non-default ingress (`Ingress#summary`, `site#c-routing-tools`).
8. **The route is matched before the body is read.** `Application#handle` asks the router for a `Router::Match` on the request's real method (HEAD as GET) and path before it reads the body. The matched route's ingress decides how the body is read and whether CSRF is checked. A request that matches no route, or matches on another method, reads and is checked with the default ingress (`Router::Match`). The same match drives dispatch, so the trie is walked once unless the request overrides its method, and matching still allocates nothing.
9. **The body is read under the matched route's policy, bounded by bytes and by count.** `RequestInput.read(request, ingress)` reads under the policy. A raw route's bytes are read up to its limit, with no transport controls, and its contract binds only the route and the query. A form route reads URL-encoded text, multipart text and `application/json` bodies within its limit; other media types answer 415. File parts are stored only for a route whose contract has an `UploadedFile` field, or for a POST whose `_method` may reach such a route at the same path; any other route stores no file, and the part's name is an unknown field. A request is bounded by count as well: its values, its file parts and a multipart body's framing each have a limit, and more of any answers 413. The numbers are in `site#c-routing-limits` and on `RequestInput::MAX_FIELDS`, `MAX_FILES` and `MULTIPART_FRAMING_BYTES`; what is stored for an upload is in `site#c-uploads-supported` and on `UploadedFile`.
10. **A form route binds a JSON object through the same contract.** A JSON body must be an object, and its scalar members bind like form fields: numbers keep their source text, `null` is absent, a member must have its field's JSON type (a string for `String`, `UUID` and `Time`, a number for `Int32`, `Int64` and `Float64`, a boolean for `Bool`), and an array binds to an `Array(T)` field, each item with its element's JSON type. The table is `RequestContract::JSON_TYPES`, and the messages and statuses are in `site#c-routing-binding`. A duplicate member is an error, and the first value wins. Other arrays and objects bind to no field. Malformed JSON, trailing data, NUL and invalid UTF-8 answer 400. `_csrf` and `_method` are ordinary members. `+json` media types are not read as JSON; such routes use `body: :raw`.
11. **Body methods are CSRF-checked unless the matched route names another credential.** POST, PUT, PATCH and DELETE are checked unless the matched route declares `csrf: false`, which requires an authenticator. On such a route the session reads empty and is never saved. The check, the token and how each client sends it are in `site#c-security-csrf`; the session rule is in `site#c-security-sessions`.
12. **The authenticator runs after the body is read and before the contract binds.** False answers 401 with no detail (`Router.unauthorized`). The authenticator runs for every method of its route, reads included. A route in the tenant block must have one, on its action or a parent, unless the action declares `open: true`; `Caramel::Router.draw` refuses it otherwise, as the tenant-route rule of [ADR 0025](0025-tenancy.md) says.
13. **A method override reaches only a route that reads its body the same way.** A POST form's `_method` reaches a route only when that route reads its body like the POST's policy: form body, same limit, same CSRF setting (`Ingress#reads_like?`). Otherwise the answer is 405. A raw route never parses `_method`.
14. **Core answers a valid contract through a hook.** The router runs `handle` and `respond` inside `Caramel::Action#__caramel_answer(contract) { … }`, whose core body only yields, like the tenancy hooks of [ADR 0025](0025-tenancy.md). An opt-in require redefines it to answer errors of its own, and core code names no library that does; [ADR 0033](sweettalk/0033-framework-boundary.md) records one. `RequestContract#field?` tells a redefinition whether the contract declares a field of a given name.

## Reasons

- Constants are visible to every later macro and carry the nilability and default information the router needs to reject unsafe parameters.
- Rejected: reading `instance_vars` in the router macro, because it returns an empty list for top-level code and verifies nothing.
- `parse` returns a contract with aggregated errors instead of raising. Forms can then re-render every message together (`contract.values`, `contract.errors`), and JSON and MRDP clients get the same error set.
- A data trie built from a compile-time table keeps the generated code small enough to read and keeps matching free of allocation and regular expressions. Because the table is verified at compile time, the runtime structure cannot drift from the declarations. The trie is built once per process.
- A protocol in core lets any type bind, not only one library's, and keeps one grammar per wire type, so a JSON client and a form get the same errors with or without field values.
- Rejected: a branch per library in the contract macro. Core would name the library, and no other type could bind.
- Rejected: any UUID spelling in routes. Uppercase, braced or unhyphenated forms would give one record several URLs, splitting caches and links.
- The policy that guards a route belongs next to the code that verifies its credential, where a compile error can insist that turning CSRF off names a verifier.
- An action inherits its parent's ingress so that an API base declares it once. A redeclaration under an authenticating parent must name an authenticator, so changing a limit can never drop authentication.
- The macro calls the authenticator as `self.name`, so a keyword or a reserved name is refused: it would not call a method.
- The body must be read differently per route (raw bytes, a limit), so the route has to be known before the body is read. Matching on the real method, and falling back to the default policy, keeps every unmatched request as guarded as before: a route's CSRF setting never applies to a request it did not match.
- JSON members bind through the same contract grammar as form text, so a JSON client and a form share one contract and one set of error messages. Checking each member's JSON type keeps `"5"` from passing as a number.
- `+json` media types are not read as JSON because their conventions for `null` and nesting mean something this binding would silently change.
- The body is read before the CSRF check and the authenticator, so what an anonymous request can make the server hold is bounded by count as well as by bytes, and a route that takes no file writes none to disk.
- Another site's form carries the browser's cookies, so only a credential a browser does not attach on its own, such as a signature or a bearer token, may stand in for the CSRF check. An empty session on CSRF-off routes turns the one authenticator that would reopen CSRF, a session cookie, into one that fails closed.
- The authenticator runs before the contract binds, so an unauthenticated caller learns nothing from contract errors.
- A `_method` override is held to the POST's own policy, so an override never skips a check.
- The answer hook's core body only yields, and Crystal inlines a method that yields, so the hook adds no call to core, and core names no library.
