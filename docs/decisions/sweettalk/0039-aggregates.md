# ADR 0039: A SweetTalk aggregate is a SugarORM schema with its own repository, lifecycle and invariants, and its entities are stored with it

Date: 2026-10-08

Status: accepted.

## Context

A domain needs a word for a root with an identity, the things it owns, the states it passes through and the rules every change keeps, and it needs ways to make, find and retire one. Several things needed a rule:

- **Storage.** What each attribute type is stored as, and who may write the rows.
- **Optional parts.** `has note : String?` stored a nullable column, but an optional value, reference or value with parts did not compile, so a model spelled one as a flag or a type code beside required columns and checked in `never` which columns the code allowed.
- **Kinds.** A transfer that is a payment has a payee and one that is a receipt has none. Each such attribute was optional and tied to its kind by a `never` written once per attribute and kind ([#262](https://github.com/caramelizedev/caramel/issues/262)).
- **Nesting.** An entity could hold no entities: a slip with its marks had to flatten the inner list onto the aggregate and key each inner row by hand, which invariants and events could not see as one thing ([#250](https://github.com/caramelizedev/caramel/issues/250), after [#167](https://github.com/caramelizedev/caramel/issues/167)).
- **Screens.** A screen decided which actions to offer by restating the lifecycle, and nothing failed when the domain added a state.

## Decision

The rules an application relies on are stated on the website ([site.html](../../../website/source/site.html)), chiefly its SweetTalk guide, in the sections cited below by anchor, and in the doc comments under [src/caramel/sweet_talk](../../../src/caramel/sweet_talk). This record states what was chosen. The constraints PostgreSQL keeps for an aggregate are in [ADR 0045](0045-database-constraints.md).

1. **Aggregates, entities and projections are SugarORM schemas.** Each is a schema in `<Context>::Rows` over the table `<context>_<name>` pluralised, written only through its changeset ([ADR 0007](../0007-sugarorm.md)); a context may not name `Rows`. `frappe db diff` derives the migrations ([ADR 0008](../0008-migrations.md)). A projection's key is uniquely indexed ([ADR 0041](0041-events.md)). The plural rules and the refusal of two declarations that give one table are in `__sweettalk_table`; the rest is in `site#c-sweettalk-aggregates`.
2. **An aggregate is a root with a typed id and is its own repository.** `aggregate Name` has `Name::Id`, `find`, `find?`, `all`, and `create` unless it declares a factory; `entity Name` inside it is stored with it (`site#c-sweettalk-aggregates`). The id's type and when it exists follow the domain's `ids` ([ADR 0033](0033-framework-boundary.md)); what `create` announces is in [ADR 0041](0041-events.md).
3. **`has` chooses the storage from the type, and `the` is never stored.** A column type is a column, a value its raw column rebuilt on load ([ADR 0040](0040-values.md)), a value with parts one column per part, `<attribute>_<part>`, an aggregate or an application's schema a foreign key whose getter returns an id, and an `Array` of its own entity a child table. `has name : Type = expression` gives a default, and a projection's or a process's attributes other than its key are optional or have a default the column takes. Any other type does not compile, nor does a name the tenant's or the parent's column takes ([ADR 0033](0033-framework-boundary.md)). `created_at` and `updated_at` read the row's timestamps. The table of types, the defaults and the refusals are in `site#c-sweettalk-aggregates` and on `has`; `pinned_at:` is in [ADR 0041](0041-events.md). `the name : Type = expression` is a derived value, computed on every read (`site#c-sweettalk-lifecycle`).
4. **A type followed by `?` is optional, for every type `has` takes.** `has x : T?` stores `x` in nullable columns, its getter returns nil while `x` is not set, and it starts as nil unless it has a default, so a factory and `create` need not set it. Entities, projections and processes take the same attributes; a projection's or a process's key cannot be optional. Their constructors accept `owner : Owner | Owner::Id | Nil`, and an entity's facts in an event carry an unset attribute as null. An optional attribute is one the thing may lack; when to choose a value with parts, `parts:`, a state or a `never` instead is in `site#c-sweettalk-aggregates`, with the storage of each optional type.
5. **A command points a reference with its writer.** `self.owner = owner` takes the aggregate, the record or its id, and nil for an optional attribute. The writer is private to an aggregate, an entity and a process, which change themselves; a projection's is public, because its `whenever` handler assigns the row it reads, except its key, which has no writer, since the row is found by it. A body that assigns `@owner` for a reference does not compile, and the message names `self.owner =` (`site#c-sweettalk-aggregates`, `__sweettalk_no_stray_writes`).
6. **A query asks an optional attribute with nil.** `where: {owner: nil}` in `finds`, `counts` and `specification` asks for the rows where it is not set, in Crystal and in PostgreSQL alike; a value with parts is asked as a whole, with nil or a value. nil is accepted only for an optional attribute. A variable that may be nil is refused as SugarORM refuses it in `where`. `order:` takes an optional attribute stored in one column (`site#c-sweettalk-aggregates`); the queries themselves are in [ADR 0035](0035-reads-and-rules.md).
7. **Aggregates and entities are built by name.** `create` and a factory both build the aggregate from keyword arguments, in which an optional attribute or one with a default may be left out wherever it is declared. An entity's `new` takes the same keyword arguments beside its positional ones; the positional form gives a default only to the trailing ones (`site#c-sweettalk-aggregates`).
8. **`parts:` ties optional attributes to the members of a closed-set value.** `has kind : Kind, parts: {payment: [payee], net_settlement: [payee, leg]}` goes on a required value with `one_of:`, in an aggregate or an entity. Each key is a member, underscored, and lists optional attributes declared above; a member it omits holds none of the attributes any member lists. A generated `never` refuses before a save, naming the member, what it holds, then what it lacks, and `as_payment` reads a listed member's parts (`site#c-sweettalk-aggregates`, `has`). These do not compile: `parts:` on a projection or a process, on anything but a required closed-set value, anything but a non-empty `{member: [attribute, …]}`, a key that is no member, an attribute not declared above, a list of entities, a required attribute, one attribute twice under a member, or a reader name the aggregate already has. The CHECK per member is in [ADR 0045](0045-database-constraints.md).
9. **An entity is stored with its parent, at any depth.** `entity Mark` inside an entity declares an entity it holds, and `has marks : Array(Mark)` stores the list (`entity`, `site#c-sweettalk-aggregates`). An entity's table is `<context>_<aggregate>_<entity>`, and a nested one's `<parent table singular>_<entity>`, pluralised: `counter_batch_slip_marks` for `Batch::Slip::Mark`. Its key to its parent is `<parent stored name>_id`, `slip_id`, named after the parent's stored name so it survives a rename, and composite with the tenant column in a tenanted context, as every `belongs_to` to a tenanted row is. A table name, or an entity's key name `fk_<table>_<parent>_id`, over 63 bytes is refused with the name at compilation, at every kind and depth. `sums` and `groups` reach an attribute of the aggregate or of an entity it holds directly, no deeper ([ADR 0035](0035-reads-and-rules.md)).
10. **Loading is one statement per list per level.** `find`, `find?`, `all` and every query read the roots, then each list of entities, then each list under those for every row of the level at once, by the parent's id, and none for an empty level. `entities: false` reads the root alone. Entities come back by id: creation order for a UUID id, insertion order for an Int64 id (`site#c-sweettalk-queries`, `Entity.__sweettalk_load`).
11. **Saving drops children first and writes only what changed.** A save deletes the rows each list was loaded with and holds no more before it writes, the rows under them first, one `DELETE` per list per level through `IN (SELECT …)` on the dropped rows, and none when none dropped; then it writes the parent only when a column changed and saves each kept entity in turn (`site#c-sweettalk-commands`, `Entity#__sweettalk_save`). An entity another parent holds is inserted anew with its own entities, and in a UUID domain a copied or rolled-back entity inserted again takes a fresh id.
12. **A lifecycle is chains of states with private movers and a public graph.** `moves open >> placed >> shipped, placed >> cancelled` gives a predicate per state and a private mover per later state, which refuses unless the current state precedes it in a chain. In memory a state is a member of the enum `Order::State`; the column stores the text `moves` spells. `Order.moves_from(state)` and `order.may_become?(state)` read the graph. A screen maps each state it offers to its command in a `case … in` over the states, which fails compilation when a state is added (`site#c-sweettalk-lifecycle`, `site#c-sweettalk-screens`, `__sweettalk_graph`). The database's check of the state is in [ADR 0045](0045-database-constraints.md).
13. **`never` and `always` hold after every command, at every depth.** `never "…" { condition }` refuses a command leaving it true, and `always` one leaving it false. A command checks every `never` and `always` of the aggregate, then of each entity at every depth, before it saves (`site#c-sweettalk-lifecycle`). An event that carries an entity carries its lists, each entity with its id: the UUID it was built with, or the Int64 its row got. Both words take `assures:`, and a calculation's are checked on `result` ([ADR 0035](0035-reads-and-rules.md)).
14. **`remove` retires an aggregate and keeps its row.** The row stays with `removed_at` set, and `find`, `find?`, `all`, every query and the command's row lock skip it (`site#c-sweettalk-queries`, `remove`).
15. **A factory replaces `create`.** `factory verb(args) do … end` builds the aggregate from the arguments named like attributes, runs its body as the first change, and checks, saves and dispatches in one transaction. An aggregate with a factory has no `create`. A factory and `create` are each timed as a `domain` span named after them, as a command is ([ADR 0046](0046-transactions.md)) (`site#c-sweettalk-factories`, `site#c-sweettalk-commands`, `factory`).

## Reasons

- Writes through `Rows` would skip invariants and the value checks made in Crystal.
- An entity's identity is its aggregate's: updating the row it was loaded from would move another aggregate's entity, and a row that a rolled-back write left does not exist.
- One column per part keeps each part queryable, with its own `CHECK` constraint. Rejected: a composite stored as one `jsonb` column; its parts could not be compared or constrained in SQL.
- Removing by a timestamp keeps every reference valid. Rejected: deleting rows; references to the aggregate would dangle.
- Rejected: `Hash` attributes. An entity holds that data in rows.
- The word "optional" already means nil in Crystal's types. Another word would make the reader learn that `String?` and `Teller?` differ.
- A writer is needed because a nilable reference otherwise has no way to change: commands reach attributes by their instance variables, and a reference's variable is `@owner_id`, of another type than the attribute. `@owner = owner` would only declare an unrelated instance variable.
- Foreign keys stay `ON DELETE` as `belongs_to` makes them; SugarORM derives a nullable key from `belongs_to owner : Row?`, so `frappe db diff` writes the nullable column, its key and its index.
- nil asked of a required attribute could never match (a scalar) or would call a method on nil (a value with parts), so the query does not compile. A variable that may be nil would match the rows whose column is NULL whenever it was nil.
- A positional constructor cannot give a default to a parameter that a required one follows, so a factory that took the optional parameter first could not compile. Building by name lifts the order.
- Rejected: a sentinel value, such as an empty text or an owner with id 0. Every reader would check for it, and a foreign key cannot hold it.
- Rejected: a union `has x : T | Other`. It is a type code in disguise, the thing optional attributes replace; each such case is a variant of its own.
- Rejected: a child table for an optional value with parts. It adds a join to every read for one group of columns, and the aggregate already owns them.
- A rule that ties one attribute's presence to another, as in "a refund has a reason", stays a `never`: `?` says an attribute may be absent, not when.
- The members and the attributes they hold are one fact; saying it at the value's attribute keeps it in one place, and the database keeps it whoever writes the row.
- The sentence of a kind's parts is what the user reads in Crystal and in a database refusal, so it names what the member holds and lacks.
- Rejected: a state that holds the columns of a kind. It ties a lifecycle to a value that is not one.
- Rejected: a `never` per kind. It cannot be a CHECK, and each author writes it again.
- A list inside an entity is the same shape as a list inside an aggregate, so it takes the same word, the same table naming and the same load, save and drop rules, applied once more per level.
- Deleting children first with `IN (SELECT …)` keeps one statement per list per level whatever the number of rows, and lets the foreign keys stay as they are.
- PostgreSQL truncates a name over 63 bytes silently, and `frappe db diff` would then plan the same change on every run: a defect found only when the diff never settles. Refusing it at compile time names the fix.
- Rejected: `ON DELETE CASCADE` on the child key. It changes the foreign keys existing applications have migrated, and hides the deletes from the statement count a spec reads, so a regression in what a save drops would pass unseen.
- Rejected: a JSON column of children. It loses each entity's id, its key to its parent, and its constraints, and an event could not carry an entity by id.
- The graph is read, not mapped to commands, because states and commands are not one to one: one state can be entered by two commands. `may_become?` answers for the graph only; a command may still refuse for another rule.
- Rejected: `to ship(…), moves: :shipped`. It is another declared list beside the body, and reading the movers from a body is inference.
