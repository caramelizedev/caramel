# ADR 0040: A SweetTalk value wraps one raw type or has parts, checks itself whenever it is built, and PostgreSQL holds every rule a column can state

Date: 2026-10-08

Status: accepted.

## Context

A domain's quantities and words were raw integers and strings: tins could be added to cents, and nothing named what a number meant. A closed vocabulary, such as the kinds of a transfer, was written four to six times: a list constant, a regular expression of the same words, a predicate for each member in Crystal, a `length:` range that fits the longest word, and a SQL list when it was checked at all. The copies drift, and the regular expression was only checked in Crystal. The screens then restated the set: they compared text and branched on members with a default arm, so a member the domain added fell into the default arm and nothing failed.

A calendar day was kept as a string value with a pattern, the calendar check written again beside it, and ranges of days read with raw SQL such as `substr(value_date, 1, 7) <= ?`. A rate was kept as a `Float64` or as a checked string, because `has rate : BigDecimal` could not be stored. Evidence and snapshots were stored as text parsed in Crystal, and not queryable. SugarORM has codecs for `date`, `numeric(P,S)` and `jsonb` columns ([ADR 0007](../0007-sugarorm.md)), and it keeps GMP out of an application that never uses `BigDecimal`, but no SweetTalk value reached a codec ([#247](https://github.com/caramelizedev/caramel/issues/247)).

## Decision

The rules an application relies on are stated on the website ([site.html](../../../website/source/site.html)), chiefly its Domain-Driven Design guide, in the sections cited below by anchor, and in the doc comments under [src/caramel/sweet_talk](../../../src/caramel/sweet_talk), chiefly the one on the `value` macro of `SweetTalk::BoundedContext`. This record states what was chosen.

1. **A value wraps one raw type, or has parts, and no other value compiles.** `value Name, Type, …, means: "…"` in a context declares an immutable value over `Int32`, `Int64`, `String`, `Date`, `Decimal(P, S)` or `Json(T)`; `value Name, means: "…" do part … end` declares one with parts. It is checked when it is built, so also when a row is loaded and when a contract field binds it, where its refusal sentence is the field's error ([ADR 0033](0033-framework-boundary.md)). A contract field binds a value from the type it wraps, and a day and a decimal from text (`site#c-sweettalk-actions`, `site#c-sweettalk-values`). Each raw type takes only its own options (`site#c-sweettalk-values`, `site#c-sweettalk-refusals`, `value`). The CHECKs of an integer's bounds and a string's length, and `otherwise:`, the sentence a value outside its bounds is refused with, are in [ADR 0045](0045-database-constraints.md).
2. **An integer value is bounded, and arithmetic keeps its type.** It takes `at_least:`, `at_most:`, `within:` and `times:`, and every arithmetic result is built, so validated, again. Two different values mixed in arithmetic do not compile; `times: Other` is the one way `*` takes another value, as in `Cents * Quantity`. The operators are in `site#c-sweettalk-values`.
3. **A string value takes a pattern and a length, or a closed list, and has no arithmetic** (`site#c-sweettalk-richer-values`).
4. **A value with parts is built by keyword and equals one of equal parts.** Each part is a column type or a value over one, and the value checks its own `never` and `always` (`site#c-sweettalk-richer-values`, `Composite`, `part`). A part may be a calendar day, stored in one `date` column; its part tuple records the codec. A part cannot be optional (`site#c-sweettalk-limits`), and an optional value that has parts and a day part keeps its all-or-none check ([ADR 0045](0045-database-constraints.md)). [ADR 0039](0039-aggregates.md) states how `has` stores the parts.
5. **A closed set is one list of literal words.** `value Kind, String, one_of: %w[payment receipt], means: "…"` is a string value whose text is one of the words, written once. The shape of a word and the lists that do not compile are in `site#c-sweettalk-richer-values` and `site#c-sweettalk-refusals`; an empty list does not compile either. `Kind::SWEETTALK_ONE_OF` holds the words, for tools that read the model; domain code reads `Kind.all`.
6. **Crystal and PostgreSQL both check the list.** Crystal refuses a text outside it when the value is built, loaded or bound, and every column that stores the value gets `check_<table>_<column>_one_of_<hash>` (`site#c-sweettalk-richer-values`). The hash is made by `__sweettalk_hashed`, the macro a lifecycle's check name comes from, over the words sorted and joined by commas, so a changed list is a new constraint. `database_check: false` keeps the list in Crystal only, and a name over 63 bytes does not compile, as for a bound ([ADR 0045](0045-database-constraints.md)). A NULL passes the check, so an optional value of the list is held to the list or to NULL (`site#c-sweettalk-aggregates`).
7. **The list's constraint can stop `frappe migrate`.** `frappe db diff` adds the check `NOT VALID` and validates it in a later step. A row that holds a text outside the list stops `frappe migrate`, which leaves the constraint `NOT VALID`, refusing new rows only, until the row is fixed; the query that finds such rows, one for each column that will store the value, is in `site#c-sweettalk-richer-values`. Adding a word to the list, or removing one, changes the hash, so the old check is dropped and a new one is added and validated the same way; removing a word needs the rows that hold it changed first.
8. **The words become methods, and a word that would hide a method does not compile.** `Kind.all`, `Kind.includes?(text)`, `Kind.receipt` and `kind.receipt?` are in `site#c-sweettalk-richer-values`. A word that names a method the value already has, such as `all`, a method every class or object has, such as `name`, `hash`, `class`, `inspect`, `to_s`, `nil` or `tap`, or a Crystal keyword, does not compile. Words with capitals map to `underscore`d names, so `USD` gives `usd?`. The `currencies` word of [ADR 0063](0063-money.md) declares a closed set of codes that ISO 4217 chose, with its own rule for a code whose methods would be taken.
9. **A closed-set value has a member enum that mirrors its words in memory.** The value also writes `enum Kind::Member`, one member per word in the order the list gives them; `kind.member` returns the value's member, and `Kind.new(member)` and `Kind.new(:receipt)` build the value of one. The column, its check and the check's hash keep the words. How a member is named is in `__sweettalk_members`.
10. **A `case … in` over the member names every one, and labels take no word.** A `case kind.member` that misses a member fails compilation with Crystal's "case is not exhaustive for enum Kind::Member", which lists the missing members. A screen labels each member with such a `case` and one catalog message per member ([ADR 0024](../0024-internationalization.md)), so a new member fails compilation at the `case` and a missing message at the catalog. A kind with parts ([ADR 0039](0039-aggregates.md)) reads its parts in the member's arm (`site#c-sweettalk-screens`).
11. **The bridge from `has` to a codec is one constant.** Every value records `SWEETTALK_WRAPS`, the name of its raw type, and `SWEETTALK_CODEC`, the codec that stores it, or `nil` (`value`). For a value with a codec `has` writes the SugarORM field of the raw type under that codec, with `?` after the type for an optional one, and `param` takes the raw type: `field settled_on : ::SugarORM::Date, codec: ::SugarORM::DateCodec`, `field rate : ::BigDecimal, codec: ::SugarORM::DecimalCodec(20, 8)`, `field evidence : ::Snapshot, codec: ::SugarORM::JSONB(::Snapshot)`. The bridge is general: any value that names a codec is stored through it, and a base added to `value` changes nothing in `has`. `frappe db diff` derives the columns and the checks. A projection's or a process's attribute that is a day, a decimal or a document takes no default, so it is optional there (`site#c-sweettalk-values`).
12. **Loading and saving carry the raw type.** A row's reader returns the raw, which the value's `new` wraps; a save writes `value.raw`. The load and save tuples, a projection's key and an entity's columns go through `raw`, so they need no case for a raw type that is not a `String`.
13. **A `Date` value is a real calendar day in a `date` column.** `value Day, Date, means: "a calendar day"` covers years 1 to 9999. `Date` names what the value wraps, as `String` does, and means `SugarORM::Date`, which `day.raw` returns. It takes no bound, pattern, length or list, and `database_check:` has nothing to keep, so it is refused. There is no `CHECK`: the column type makes PostgreSQL refuse a day that does not exist, and `SWEETTALK_CHECK` is `nil`. For a table that holds the day as `text`, the differ derives SugarORM's checked retype ([ADR 0007](../0007-sugarorm.md)). The words of a day, and the refusal of a text or a result outside the calendar, are in `site#c-sweettalk-richer-values`.
14. **There is no `Day.today`.** An application passes its day to the command that needs it; `Day.of(time)` reads the time's own calendar day, with no conversion to UTC (`site#c-sweettalk-richer-values`).
15. **A day is a `date` in queries and ISO text everywhere else.** `finds`, `counts` and `specification` ([ADR 0035](0035-reads-and-rules.md)) take a closed, beginless or endless `Range` of days through the codec's `ORDERABLE` ([ADR 0007](../0007-sugarorm.md)), `order:` sorts the column, and days compare in Crystal and in PostgreSQL alike. A specification binds a day through the row's own encoder for the column, so it is the same `YYYY-MM-DD` text that `finds` binds. A day in an event field (`carries:` or declared), a job payload or a projection key is written as `"2026-03-01"` and read back by `Day.new`, and it is a JSON string in a `JSON::Serializable` type. A contract field binds a day from `YYYY-MM-DD` as a `Caramel::FieldValue(String)`, and the value's refusal sentence is the field's error ([ADR 0033](0033-framework-boundary.md), [ADR 0003](../0003-routing-and-ingress.md), `site#c-sweettalk-actions`).
16. **A `Decimal(P, S)` value is an exact `BigDecimal` in a `numeric(P,S)` column, opt-in by one require.** `value Rate, Decimal(20, 8), at_least: "0", at_most: "1", means: "…"` keeps P digits in all and S after the point, with `1 <= P <= 1000` and `S <= P`; `rate.raw` is the `BigDecimal`. It takes `at_least:`, `at_most:` and `database_check:`, and no `within:`, `times:`, `matches:`, `length:` or `one_of:`. `require "caramel/sweet_talk/decimal"` requires `big`, the codec and `caramel/sweet_talk`. Neither `sugar_orm` nor `caramel/sweet_talk` requires it, so a program that declares no decimal value links no GMP, and a `Decimal(…)` value without it fails compilation naming the require. `SugarORM::DecimalCodec(P, S)` stores the value ([ADR 0007](../0007-sugarorm.md)); its doc comment states the column type, the text it writes and what it refuses, and `SugarORM::Decimal.plain` and `.fits` are the words the codec and the value share. The codec's `encode` refuses with `ArgumentError`; a decimal value refuses first, when it is built.
17. **A decimal's bounds are decimal text, and they join the CHECK's name.** `at_least: "0"` and `at_most: "1.5"` are string literals of digits with at most one point. A literal with more than S decimals, or more than P - S digits before the point, is refused at compile time. `SWEETTALK_CHECK` is `{"column", suffix, SQL}`, `"rate" BETWEEN 0 AND 1`, named `check_<table>_<column>_between_0_and_1` (`from_0`, `to_1_5`; `.` becomes `_` and a leading `-` `minus`), so a changed bound is a new constraint, as a length's is. `database_check: false` keeps the bounds in Crystal and lets them name a constant.
18. **Every build of a decimal refuses what the column would round or overflow, then what the bounds exclude.** `Rate.new(text)` reads digits with at most one point and refuses other text; `Rate.new(BigDecimal)` and `Rate.new(Int)` wrap. `+` and `-` take the same value, `*` an integer, `<=>` and `sort` compare by value whatever the scale written, `to_s` is the plain digits and `zero` is `0`. The refusal sentences are in `site#c-sweettalk-values`.
19. **A decimal is text everywhere but in the column.** It is the JSON string `"0.05"` in an event field, a job payload, a projection key or a `JSON::Serializable` type, and is read back by `Rate.new`. A contract field binds it from text as a `Caramel::FieldValue(String)` ([ADR 0033](0033-framework-boundary.md)).
20. **A `Json(T)` value is a document kept whole in a `jsonb` column.** `value Evidence, Json(Snapshot), means: "…"` is over a `JSON::Serializable` type declared before it, and `value Note, Json, means: "…"` over `JSON::Any`; it is stored through `SugarORM::JSONB(T)`, with no bound, pattern, length, list or `database_check:`, so `SWEETTALK_CHECK` is `nil`. It equals another with an equal document, and in JSON it is the document itself. How it is built, and that its `raw` is the document, are in `site#c-sweettalk-values`.
21. **A JSON value is asked only for equality or absence.** `where: {evidence: evidence}` and `where: {evidence: nil}` in `finds`, `counts` and `specification` compare the whole document; a Range fails compilation at SugarORM's typed `where`, and `order:` on one is refused by the context. Querying inside the document (`@>`, GIN) waits on [#280](https://github.com/caramelizedev/caramel/issues/280) (`site#c-sweettalk-limits`).
22. **Arrays of scalars stay refused.** A list belongs in a `Json(T)` value whose type holds it, or in an entity.

## Reasons

- Tins plus cents is a bug the compiler can catch.
- SugarORM's codecs store a value only as text in a `numeric`, `jsonb`, text or `date` column, so integer values keep integer columns and string values text columns, with no codec.
- A single list read three ways, by Crystal, by PostgreSQL and by predicates, cannot disagree. The check is exact, unlike a pattern, so the reason [ADR 0045](0045-database-constraints.md) gives for keeping patterns in Crystal, that PostgreSQL reads them differently, does not apply.
- Predicates replace `kind == "receipt"`, a string compared by hand at every use, with a method that fails to compile when the word is misspelled.
- Hashing the list into the name follows a lifecycle's state check ([ADR 0045](0045-database-constraints.md)): SugarORM compares an expression check by name, so a changed list must change the name for `frappe db diff` to replace it.
- A closed set is a value, not an enum type, because the stored form stays text, which is what existing columns hold, and the list stays a CHECK that a later release can change. A PostgreSQL enum type cannot drop a value.
- **Rejected: a Crystal `enum` as the stored type.** It would store numbers or need its own column mapping, and the words in existing data would not map. An enum that only mirrors the text in memory, `Kind::Member`, needs neither and keeps the text in the column; `moves` keeps the same pair for a lifecycle's states, an enum in memory and the word in the `state` column ([ADR 0039](0039-aggregates.md)).
- **Rejected: groups of words, as in `trade: %w[receipt vendor_payment]`.** A subset is a rule over the value, so it belongs to a method or a specification on the aggregate that holds it.
- Crystal proves a `case … in` exhaustive and refuses its `else`, so a member added to the list fails compilation at every screen that branches on it. A `when` with an `else` sends the new member to the default arm in silence.
- The enum belongs to the value, so kinds with parts and later declared subsets build on it, and each subset method's body becomes exhaustive too.
- Labels need no new word while a `case` and a catalog already fail compilation on a gap.
- **Rejected: a label word**, `means:` per member or a `label` read from a catalog group named for the value. The first is a second list; the second ties `caramel/i18n` to SweetTalk.
- **The codec is already the stored form of a day.** The day then sorts, compares and ranges in PostgreSQL as a `date`, so a month of days is a range, not a `substr`.
- **One constant, not one case per base.** The macros that load, save, bind and compare a value already pass its `raw`; the only place that must know a codec is the `field` line, and the places that bind a value without SugarORM's typed `where`, the specification's conditions. A general mechanism costs no more than a `Date`-only one, and decimals and documents use it with no change to `has`.
- **No `CHECK` on a day.** The `date` column type ([ADR 0007](../0007-sugarorm.md)) already refuses a day that does not exist, so a regular expression would say less than the column.
- **Refuse, do not clamp.** A day outside the calendar is a mistake in the caller's data.
- **No `today`.** A word that reads the clock reads UTC, and a day near midnight is another day in the user's zone. A command that takes the day as an argument is testable and says which zone it means, and `Day.of(time)` reads the zone the time carries.
- **Rejected: a `Day` that stores text.** Its `raw` would be text for good, text would be permanent API, and every application that adopted it would migrate to `date` later: a `date` column cannot be reached from text without a migration.
- **Rejected: `Time` at midnight.** It stores a time of day that nothing means and moves by a day when a zone is applied.
- **Rejected: optional parts inside a value.** The all-or-none check of an optional value covers it as a whole, and a part that is optional alone is a change of its own.
- **A decimal is text everywhere but in the column.** `BigDecimal#to_s` prints an exponent past some size, and a JSON number is read as a float by most readers, so the codec and the value write their own plain digits and carry them as a string, and no reader rounds one through a float.
- **Refuse at the write, not round.** `numeric(20,8)` rounds a ninth decimal silently and raises on a thirteenth digit; a value that cannot be stored exactly is a mistake in the caller's data, and the value and the codec say so before PostgreSQL does, so PostgreSQL never rounds or overflows one.
- **The bound joins the name.** The differ compares an expression check by name only, so a bound that is not in the name would never be replaced. A bound written past the column's digits would never hold on the column, so it is refused at compile time.
- **Opt-in by one require.** GMP is a link-time dependency, and a program that stores no decimal should not carry it ([ADR 0007](../0007-sugarorm.md)). One require is cheaper than a flag.
- **Equality only on a document.** PostgreSQL orders `jsonb` by its own rules, which no domain means, so a document has no order; containment and indexing are a query feature of their own.
- **Rejected: `Float64` values.** A rate of `0.1` is not representable, and a sum of rates drifts.
- **Rejected: integer minor units for rates.** A rate has no unit to count in. Money counts minor units with its currency beside them, in `caramel/sweet_talk/money` ([ADR 0063](0063-money.md)).
- **Rejected: bounds as number literals.** `at_least: 0.1` is a `Float64` in Crystal and would round before it reached the CHECK; text keeps the digits the author wrote.
- **Rejected: a `Json` value with `order:`.** It would sort by `jsonb`'s internal order, which reads as random to a domain.
- **Rejected: linking GMP in `caramel/sweet_talk`.** Every application would pay for a value most do not declare, against [ADR 0007](../0007-sugarorm.md).
