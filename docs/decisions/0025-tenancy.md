# ADR 0025: Multi-tenancy is opt-in: one require scopes rows, routes, jobs, cache keys and channels to the tenant the first path segment names

Date: 2026-10-03

Status: accepted.

## Context

An application that serves several organizations must keep each one's rows apart. It must be able to opt in, pay nothing when it does not, and plug tenancy in and out again.

Every record is keyed by a UUIDv7 the application mints, with Int64 as an opt-in ([ADR 0007](0007-sugarorm.md)). A tenant is a record too, and its id appears in every cache key, PubSub channel and job payload its work writes, so both key types need a form there.

## Decision

The rules an application relies on are stated on the website ([site.html](../../website/source/site.html)), chiefly its Multi-tenancy guide, in the sections cited below by anchor, and in the doc comments under [src/caramel/tenancy](../../src/caramel/tenancy) and in [src/sugar_orm/tenancy.cr](../../src/sugar_orm/tenancy.cr). This record states what was chosen.

1. **Core carries hooks whose bodies are identities.** `Application#handle` routes through `tenanted`, which only yields. `Caramel.tenant_path(path, of:)`, `Caramel::Cache.scoped`, `Caramel::ColdBrew.carry` and `Caramel::ColdBrew.channel` return their input, and `Caramel::ColdBrew.carried` only yields. The doc comment on each names what `caramel/tenancy` puts there; `Caramel::Cache.clear`, `Caramel.resource_paths` and `Application#failure` state the rest of core's side, and the language switcher's link passes through `tenant_path` (`site#c-tenancy-views`). A job `param caramel_tenant` is a compile error. How SweetTalk follows the tenant is in [ADR 0033](sweettalk/0033-framework-boundary.md).
2. **`require "caramel/tenancy"` is the only way in.** It redefines the hooks, and its `macro finished` guard refuses a program that has the require and no tenant block. The documented API is `Caramel::Tenancy.with`, `without`, `each`, `current` and `current?`; every other method is `# :nodoc:`. The tenant is bound to the fiber for a block and the previous binding is restored afterwards (`SugarORM::Tenancy.bind`).
3. **The first path segment names the tenant.** `Caramel::Router.draw` takes one `tenant App::Account, by: :slug do … end` block, and its routes match in a tree of their own (`Router::Tree`). `Application#tenanted` reads a first segment that is a lowercase DNS label, not a central route's first segment and not a locale prefix, as a slug; what it does with the slug, with an unknown one and with every other request is in its doc comment, and a streamed body runs in the request's tenant (`Tenancy.streamed_in`). The tenant comes before a locale prefix. `cs.validate_tenant_slug(:slug)` accepts only a slug the router would read. The block's shape, the `/:tenant` listing and the route refusals are in `site#c-tenancy-routes`, `site#c-tenancy-refusals` and `site#c-routing-checks`; `tenant`, `tenant_path` and the prefix order in `site#c-tenancy-views`; the slug rules in `site#c-tenancy-slugs`.
4. **A tenant route fails closed.** `Caramel::Router.draw` refuses a route in the tenant block whose action, or a parent of it, neither names an authenticator with `ingress authenticate:` nor declares `ingress open: true`, the ingress declaration of [ADR 0003](0003-routing-and-ingress.md). `open: true` serves the route to anyone in the tenant and never combines with `authenticate:` (`site#c-security-ingress`). The refusal's text is in `site#c-tenancy-refusals`.
5. **Membership is the application's.** Tenancy decides which rows a request sees. Whether a user may act in `acme` is the application's ingress check, `ingress authenticate: :member?`; an action for anyone in the tenant declares `ingress open: true`. The generated session-held membership is a starting point the application replaces with a table of its own (`site#c-tenancy-slugs`, `site#c-tenancy-gaps`).
6. **SugarORM's `tenant account : Account` is a `belongs_to` that also scopes.** Its column is system-managed: never a changeset param, never NOT NULL-checked. It stays preloadable. The column is `uuid` or `bigint` after its target's key, and the target may be declared later in the program. With a tenant bound, queries (locking ones included), `BelongsTo` and child preloads, updates and deletes add the tenant's predicate, and inserts and upserts stamp it. With none bound, a tenanted statement raises `SugarORM::Tenancy::Missing`, unless it runs inside `without`; an insert raises even there. Raw `SugarORM.sql` is not scoped. The outcomes an application sees are in `site#c-tenancy-schema`, `site#c-sugarorm-queries`, `site#c-sugarorm-saving` and `site#c-sugarorm-sql`. Compile errors refuse a `tenant` without the require, a second `tenant`, a target that is not a schema or is tenanted, and a target other than the routes' model.
7. **PostgreSQL keeps a reference inside its tenant.** A tenanted table gets the unique index `index_<table>_on_account_id_and_id`, first among its indexes. A unique explicit index also holds `account_id` and keeps its name, so it is unique per tenant. A `belongs_to` whose target is tenanted is the composite key `(author_id, account_id) → (id, account_id)`. Such a key cannot use `on_delete: :set_null`, because it holds the tenant column, which is NOT NULL; the refusal is in `site#c-sugarorm-schemas`.
8. **Foreign keys span several columns.** `SugarORM::Catalog::ForeignKey` holds `columns` and `references_columns`. The differ drops every changed key, and every undeclared key it named (the ownership rule for undeclared keys of [ADR 0008](0008-migrations.md)), before any other statement. It adds a composite key on a new table's own rows after that table's indexes. It halts a key that would wait on a unique index it only builds CONCURRENTLY; the halt prints the index to build first.
9. **A tenant is keyed by UUID, or by Int64 as an opt-in.** `frappe make tenancy` writes a UUID key and `--int64` writes an Int64 key. A tenant resource's `<tenant>_id` column follows the tenant model's `field id` line (`site#c-tenancy-enable`).
10. **A job runs in the tenant it was enqueued in.** The payload carries the tenant's id under `"caramel_tenant"` (`Tenancy::CARRY_KEY`): a JSON number for an Int64 tenant and a string for a UUID tenant. A job whose tenant is gone fails with `Caramel::Tenancy::Gone`, a job enqueued with no tenant runs with none, and a `spawn`ed fiber starts with none (`site#c-tenancy-background`).
11. **Cache keys and PubSub channels carry the bound tenant's prefix.** The prefix is `t`, the tenant's id and `:`. An Int64 id is written in digits: `t<digits>:`. A UUID is written as 25 lowercase base-36 characters (`Caramel::ColdBrew.short_id`), which makes its prefix 27 characters. A prefixed channel stays within 63 characters. With no tenant bound, a name that starts with either form is refused, except inside `without`, and what `Cache.clear` deletes follows the binding. The refusals and the three cases of `clear` are in `site#c-tenancy-background` and `site#c-coldbrew-cache`, and in the doc comments of `Tenancy::PREFIXED`, `Tenancy.scoped`, `Caramel::Cache.clear` and `Caramel::ColdBrew.channel` in `src/caramel/tenancy/runtime.cr`.
12. **Frappé writes the tenant, then resources that belong to it.** `frappe make tenancy MODEL [--int64]` writes the tenant's schema, changeset, migration, sign-up page and home, and wires the require, the tenant block, the path helpers, `member?` and the spec helpers. Afterwards `frappe make resource` writes resources that belong to the tenant, and `--central` writes one every tenant shares, the same as a plain application's. What each command writes is in `site#c-tenancy-enable`, `site#c-tenancy-resources`, `site#c-tenancy-slugs`, `site#c-tenancy-testing` and `site#c-commands-frappe`.
13. **Plugging in on existing data is done by hand, in order.** Adding `tenant` to a populated table halts the differ. A hand-written migration adds the column, a second builds the `(tenant, id)` index, `frappe db diff` then derives the keys, and every queue is drained before the deploy. The steps, the halt's text and the index SQL are in `site#c-tenancy-existing`.
14. **Plugging out is four steps by hand.** First, make every value of a per-tenant unique index unique across tenants: the differ rebuilds those indexes without the tenant column. Second, remove the `tenant` lines and record `drop_column :account_id`. Third, remove the require and the tenant block together, moving the block's routes out; either one alone is a compile error. Fourth, run `frappe db diff`.

## Reasons

- One require replaces identity hooks, so a plain application compiles none of the tenancy code; `scripts/check tenancy` proves it on the binary. [ADR 0024](0024-internationalization.md) enters i18n the same way, through one require over identity hooks.
- Scoping fails closed. Crystal applications today scope with an explicit `where`, and one forgotten call leaks another tenant's rows; Ecto's `prepare_query`, Ash and activerecord-tenanted raise instead.
- Tenant routes fail closed for the same reason. The slug alone selects the tenant and the session cookie spans every tenant, so a user signed in under `acme` reached `/globex/books/1` until each action checked membership by hand ([#99](https://github.com/caramelizedev/caramel/issues/99)); the compile check makes the omission a build error, `open: true` keeps a public tenant page honest, and the generated session-held membership gives a new application a working default to replace.
- Composite keys let PostgreSQL refuse a reference to another tenant's row, even from raw SQL, and the `(tenant, id)` index serves scoped reads.
- The tenant is bound per fiber and restored, as `Log.with_context` is, because HTTP::Server serves keep-alive requests on one fiber. Every request outside a tenant routes with no tenant bound, so a reused fiber carries none in.
- A path prefix needs no DNS or certificates in development, and the slug is a DNS label, so subdomains can follow without changing application code.
- A job carries each tenant id in its own JSON type, a number for an Int64 and a string for a UUID, so an Int64 tenant's queued payloads read unchanged.
- The survey behind these choices is [research/multi-tenancy.md](https://github.com/caramelizedev/caramel-notes/blob/main/research/multi-tenancy.md) in caramel-notes.
- **Rejected: the hyphenated UUID as the tenant prefix.** At 38 characters it would leave a channel 25; base 36 fits the 128 bits in 25 characters and keeps the prefix's alphabet of digits and lowercase letters, so the cache patterns stay exact.
- **Rejected: subdomains as the first way to name a tenant.** They need wildcard DNS and certificates before the first page works.
- **Rejected: a schema per tenant.** SugarORM checks out a pooled connection per statement and caches prepared statements; introspection, migrations, Corretto, Latte and Cold Brew all assume one schema; and signing up would run DDL inside a request.
- **Rejected: a database per tenant.** It multiplies pools, migrations and backups.
- **Rejected: row-level security as the first layer.** Owners bypass it without FORCE, and the setting must be bound per transaction, since crystal-db sets a connection up only when it opens one. It can be added later as a second layer.
- **Rejected: explicit scope arguments,** as in Phoenix, or `where(org_id: …)`. Both fail open when one call forgets.
- **Rejected: `tenant: true` on path helpers,** and **a separate configuration declaration.** The router's tenant block already names the model, the slug and the tenant routes.
- Deferred: host-based identification and row-level security.
