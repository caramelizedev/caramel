# ADR 0063: Money is an opt-in SweetTalk module that counts minor units in a type per currency

Date: 2026-11-07

Status: accepted.

## Context

An amount whose currency is chosen per row was two attributes paired by convention: a `Cents` value beside a `Currency` value. Adding amounts in two currencies compiled and returned a wrong number, any three capitals were stored, text was rounded silently on parse, and a conversion checked the amount's currency against the rate's at run time, through strings. A Crystal generic argument is a type or a number, never a string, so a currency in a type needs a type per currency.

## Decision

The words, their options and every refusal are stated on the website ([site.html](../../../website/source/site.html)) in `site#c-sweettalk-money`, with the compile errors in `site#c-sweettalk-refusals`, and in the doc comments of [src/caramel/sweet_talk/money.cr](../../../src/caramel/sweet_talk/money.cr) and [src/caramel/sweet_talk/money](../../../src/caramel/sweet_talk/money). This record states what was chosen.

1. **`require "caramel/sweet_talk/money"` is the module.** It is a module under the modules rule of [ADR 0030](0030-scope-and-modules.md) and requires `caramel/sweet_talk/decimal`. `currencies`, `quote` and `allocation` without it fail compilation naming the require, from stubs the core defines and the module redefines, and a program without it holds none of its code (`site#c-sweettalk-money`).
2. **`currencies` declares `Currency`, a closed set of codes, and a marker type per code.** `currencies %w[USD EUR JPY], exponent: {XAU: 4}, means: "…"` stands in a context or a kernel, once. `Currency` is a closed set of three-capital codes, checked when it is built and by a CHECK on every column that stores it, as the closed sets of [ADR 0040](0040-values.md) are (the constraint's name is in `site#c-sweettalk-richer-values`). Each code is also a marker type, `Currency::USD`, with the constants `CODE` and `EXPONENT`. Where a `one_of:` word that names a taken method does not compile, a code whose methods would hide ones every value or object has, such as ALL (`all`) and TRY (`try`), gets no `Currency.all`-style methods, and `Currency.new` builds it. The methods are in `site#c-sweettalk-money` and on `currencies`.
3. **Minor units come from ISO 4217 list one.** The list published 2026-09-17 was fetched on 2026-11-07 from <https://www.six-group.com/dam/download/financial-information/data-center/iso-currrency/lists/list-one.xml>: 165 codes with 0 to 4 minor units and 13 marked N.A., embedded as Crystal literals in `money/iso4217.cr` (`Money::ISO4217`, `Money::ISO4217_WITHOUT_UNITS`). A code outside the list, or marked N.A., takes `exponent:`; one the list gives, or a code `exponent:` names that is not listed, fails compilation. The range of `exponent:` is in `site#c-sweettalk-money`.
4. **`Minor(Currency::USD)` is a signed `Int64` count of minor units that takes only its own currency.** Money counts minor units with its currency beside them; [ADR 0040](0040-values.md) keeps decimals for a number with no unit to count in. `Minor(USD) + Minor(EUR)` fails in Crystal's overload resolution, at the caller's line, naming both types. Text with more decimals than the currency keeps is refused by `parse`, and `round(text, rounding:)` rounds on purpose. The operators, the text forms and the refusal's message are in `site#c-sweettalk-money`.
5. **`Amount` is the union of every member's `Minor`.** It is the type of an amount whose currency is data, and two `Amount`s added fail compilation. `same(a, b) { |x, y| … }` is a macro with one branch per currency that runs the block on two amounts of one currency and refuses two; `by_currency` totals each currency; `Amounts` builds the member a currency names (`site#c-sweettalk-money`, `Amounts`).
6. **Every stored amount carries its currency.** `has original : Money::Amount` stores a currency column under the currencies' CHECK beside a `bigint`, loaded through `Amounts`; an optional amount stores both or neither, as an optional value with parts does ([ADR 0045](0045-database-constraints.md)), under `check_<table>_<name>_all_or_none`. `has fee : Minor(Currency::USD)` stores the same two columns and refuses another currency when it loads. `has` and event fields find the loader through `SWEETTALK_LOADER` on the marker type. The column names, the JSON an event carries and how `finds` and `specification` compare an amount are in `site#c-sweettalk-money`.
7. **A rate is a stored value whose currencies are data, kept as an exact fraction.** `quote Rate, rounding: :half_up, means: "…"` declares `RateDay`, a day, and `Rate`, a value with parts stored one column each: `from` and `to`, two different currencies, `numerator` and `denominator`, the fraction in lowest terms and above zero, `day` and `source`. `Rate.of(BigRational, …)` refuses a fraction past `Int64`. `amount.convert(rate)` returns the amount in `to`, rounded as the quote declares, and refuses an amount in another currency than `from`. `inverse` and `through(other)` are exact cross rates; `through` joins rates of one day, and their sources. A rate's window, a fallback and an override are the application's. `Rate.parse`, the four rounding modes and the refusals' messages are in `site#c-sweettalk-money` and on `quote`.
8. **An allocation is a calculation that splits an amount by weights, exact to the minor unit.** `allocation split, of: Money::Amount, by: Weight, remainder: :largest_fraction, means: "…"` declares a calculation ([ADR 0035](0035-reads-and-rules.md)), `split(total, weights : Hash(Int64, Weight))`. Each key gets the floor of its exact share, a `BigRational`, and `remainder:` says where the units left go. Ties go by key, smaller first, and `ties:` takes only `:key`. Generated rules on `result` state the split's identities, and `Corretto.property` ([ADR 0010](../0010-corretto.md)) draws hashes and amounts to run them, an amount as a whole number of minor units in one of the currencies (`site#c-corretto-properties`). A float in its types or block fails compilation at that line. The remainder modes, `per:`, the refusals and the generated rules are in `site#c-sweettalk-money` and on `allocation`.
9. **`sums` and `groups` add up amounts, an `Amount` per currency.** The words are those of [ADR 0035](0035-reads-and-rules.md). A `Minor(Currency::USD)` adds up as a number: `sums` returns one, zero when nothing matches, and `groups` one per key. A `sums` of an `Amount` returns `Hash(Currency, Amount)` in one statement grouped by `<name>_currency`: a total per currency that has rows, in code order, as `by_currency` totals loaded amounts, `{}` when nothing matches; an optional amount's unset rows add nothing. A `groups` that adds up an `Amount` does not compile. `by:` an amount groups by its currency, as `{by: Currency, total: …}` (`sums`, `groups`, `site#c-sweettalk-money`).
10. **Every refusal has a fixture, and the module is proved absent on the binary.** Each refusal has a fixture in `sweet-talk-compilation`, which also builds `spec/fixtures/sweet_talk/money.cr` to prove on the binary that only a program with the require holds the module's code. `spec/sweet_talk` runs amounts, rates and allocations on PostgreSQL with the other modules, and catches a split seeded one unit short within 200 drawn cases.

## Reasons

- **Marker types keep the mix a type error.** Crystal reports `Minor(USD) + Minor(EUR)` at the caller's line with both types, so no macro needs the receiver's type, which is unknown when a macro expands (the limit [ADR 0046](0046-transactions.md) records), and no error points into generated code. The reason of [ADR 0040](0040-values.md) against an `enum` as the stored type stands: a marker stores nothing, and the column keeps the code as text.
- A code whose methods would be taken gets none instead of failing compilation, since ISO 4217 chose the codes.
- **`same` is a macro.** A block given to a method called on a union is typed once for every member, so its arguments become unions again; a branch per currency keeps each block's arguments one type, and errors in the block point at its line.
- **A rate's currencies are data.** Rates are stored and loaded like amounts, so a typed `Rate(A, B)` would need a union of every pair of currencies; `convert` checks the amount against `from` instead, and the result is an `Amount`.
- **Refuse excess decimals.** A third decimal on a dollar is a mistake in the caller's data, as a ninth on a `Decimal(20, 8)` is ([ADR 0040](0040-values.md)); an import rounds by saying how.
- **One load path.** A currency column beside every amount, under a CHECK, holds for a reporting currency too, so no amount reads its currency from the tenant or a setting.
- **An allocation is a calculation.** Its identity, that the parts sum to the total, is a rule on `result` that every call checks and `Corretto.property` draws cases against, so a hand-written split one unit short fails within 200 cases. Ties by key make the result one function of its arguments, and refusing floats at the author's line keeps the shares exact.
- **A total of amounts is per currency.** Adding `original` without its currency adds euros to yen; grouping by the currency column keeps them apart, and `Hash(Currency, Amount)` is the shape `by_currency` answers.
- **Rejected: an `Amount` composite whose `+` refuses a mismatch at run time.** It compiles the mix the type refuses.
- **Rejected: a role parameter, `Minor(Reporting)`, resolved per tenant.** A second load path, and a column that says nothing alone.
- **Rejected: `Float64` and rounding on parse.** A float drifts, and silent rounding hides the mistake the refusal names.
- **Rejected: a tie broken at random, or by insertion order.** The same weights would split two ways, and a property case could not be replayed from its seed.
- **Rejected: `Array(Amount)` for a sum of amounts.** A lookup by currency would scan it.
- **Rejected: `by: Line.original.currency`.** An amount's one key is its currency, and an aggregate's own amount would need another form.
