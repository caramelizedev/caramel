# ADR 0045: SweetTalk declares the rules a row alone decides as PostgreSQL constraints, and answers a violation of a declared one as a refusal

Date: 2026-10-09

Status: accepted.

## Context

SweetTalk checks a value's bounds, a lifecycle's states and an aggregate's invariants in Crystal. A write that goes around it, through `Rows`, a SQL backfill or another service, skipped those checks. A lifecycle's `state` column took any text, and a two-word state written without its underscore was missed by `finds state:`. A row could hold a receipt with a payee, or half of a value with parts.

`has` took no options, so an aggregate could not say that a label, a code or an operation key is unique, that a business key is looked up and so indexed, or that a shape such as "a pending line carries no amounts" holds in the database. The only unique index SweetTalk wrote was a projection's or a process's key. An application that needed idempotency kept a table of claims beside its aggregates, checked uniqueness with a read under a row lock, which a caller could skip, and wrote a hand migration for an index, whose violation then surfaced as a raw `SugarORM::UniqueViolation` instead of a refusal ([#166](https://github.com/caramelizedev/caramel/issues/166)).

## Decision

The rules an application relies on are stated on the website ([site.html](../../../website/source/site.html)), chiefly its SweetTalk guide, in the sections cited below by anchor, and in the doc comments under [src/caramel/sweet_talk](../../../src/caramel/sweet_talk). This record states what was chosen. The aggregates, attributes and lifecycles the constraints belong to are in [ADR 0039](0039-aggregates.md), and SugarORM's index and check lines in [ADR 0007](../0007-sugarorm.md).

1. **A value's bounds and length are CHECK constraints on every column that stores it.** An integer value's bounds and a string value's `length:` are SugarORM `check` constraints on each such column, a composite's part columns included: `check_<table>_<column>` for bounds, and `check_<table>_<column>_length_<lo>_<hi>` for a length (`length_from_<lo>` or `length_to_<hi>` when one end is open), so a changed length is a new constraint. Such bounds are integer literals; `database_check: false` keeps a value's bounds in Crystal only, where they may name a constant, and a pattern is checked in Crystal only (`site#c-sweettalk-values`, `site#c-sweettalk-richer-values`). SweetTalk's changesets do not map these constraints: SweetTalk refuses first, so a violation from its own write raises `SugarORM::CheckViolation`. Any other bound, a constraint name over PostgreSQL's 63 bytes, and two declarations whose names give one table do not compile.
2. **A lifecycle's states are a CHECK on its `state` column.** A lifecycle stores each state as `moves` spells it, and the column has the check `check_<table>_state_<hash>`, `"state" IN ('open', …)`. The hash is of the states, sorted and joined by commas, so a changed list of states is a new constraint (`site#c-sweettalk-lifecycle`). A name over 63 bytes does not compile (`site#c-sweettalk-refusals`).
3. **An optional value with parts is set whole or not at all.** The columns of an optional value with more than one part carry the check `check_<table>_<attribute>_all_or_none_<hash>`, `num_nonnulls(…) IN (0, <parts>)`. The hash is of the value's part names, sorted and joined by commas, so a part added to the value replaces the constraint. A row that holds only some of the parts is also refused when it is loaded, naming the value. A value's own checks stay on the part's column and pass a NULL (`site#c-sweettalk-aggregates`).
4. **A kind's parts are one CHECK per member of the value, listed or not.** For `parts:` on a closed-set attribute, each member has `"kind" <> 'payment' OR (num_nulls(<set columns>) = 0 AND num_nonnulls(<unset columns>) = 0)`, with the columns of a reference, a part of a value with parts, or the attribute; a conjunct with no columns is dropped. It is named `check_<table>_<attribute>_<member>_<hash>`, and a violation refuses with the sentence the generated `never` gives (`site#c-sweettalk-aggregates`).
5. **An aggregate or an entity declares its own unique indexes, indexes and checks.** `has` takes `unique:`, `index:` and `check:` for one attribute, over the attribute's stored columns. The words `unique`, `index` and `check` cover several attributes declared above them, or `state` once `moves` is. A `check` names its SQL and requires its sentence; `unique` defaults to one that names its attributes. A projection and a process take none of these: their `key` is their identity and its unique index is theirs. The forms, the sentences and the refusals are in `site#c-sweettalk-aggregates`, `site#c-sweettalk-refusals` and on `has`, `unique`, `index` and `check`.
6. **The DDL is SugarORM's, and a hashed name makes an edit a replacement.** A unique or plain index is the schema's `index` line, named and shortened past 63 bytes by SugarORM ([ADR 0007](../0007-sugarorm.md)), as a reference's, a key's and a tenant's index are; a reference's foreign-key name is shorter. In a tenanted context SugarORM appends the tenant column to a unique index, so a value is unique within each tenant. A declared check is the schema's `check :name, "sql"` line, named `check_<table>_<name>_<hash>` with the hash of its SQL; a name over 63 bytes does not compile (`__sweettalk_constraint`). Every hashed name is the FNV-1a 32-bit hash as eight hex digits, from one macro (`__sweettalk_hashed`). On an existing table `frappe db diff` builds the index `CONCURRENTLY` and adds the check `NOT VALID`, then validates it in a migration of its own, which the zero-lock linter accepts ([ADR 0008](../0008-migrations.md)).
7. **A violation of a declared constraint is a refusal.** Each aggregate and entity records its constraint names with their sentences (`SWEETTALK_REFUSALS`). Its save rescues `SugarORM::UniqueViolation` and `CheckViolation` and raises `SweetTalk::Refusal` with the sentence the constraint maps to; a constraint SweetTalk did not declare stays the error it is. A command's refusal rolls the transaction back, clears the events and reloads the aggregate, and an action answers 422 ([ADR 0033](0033-framework-boundary.md)); a `create` or a factory raises and leaves no row.
8. **An entity's `unique` holds within its parent.** The parent is the aggregate or entity that holds it, and the index leads with the parent's column, `(<parent>_id, columns)`, so two slips may each hold a mark with the same note. A save deletes the entity rows it loaded and dropped before it writes, so an entity replaced by one with the same value saves. Two entities that swap their values still violate: the index is not deferrable.
9. **A value's bounds take `otherwise:`.** `otherwise: "A balance cannot go below zero."` on a value is the sentence every value outside its bounds is refused with, wherever the value is built: a build, an arithmetic result, a contract field or a load. It goes with an integer's bounds, `matches:`, `length:`, `one_of:` and a decimal's `at_least:` and `at_most:`; a decimal's shape refusals keep theirs, and the word does not compile on a value without bounds, a day, a document or a value with parts (`site#c-sweettalk-values`, `value`). The database check is unchanged: a write around the value still meets the raw `CheckViolation`.
10. **A new constraint can stop a migration.** `frappe db diff` adds a check and a new foreign key `NOT VALID` and validates them in a later step. Rows written before them that break one stop `frappe migrate`, which leaves the constraint `NOT VALID` (it refuses new rows, not old ones) until those rows are fixed. A new unique index over rows that already hold duplicates fails `CREATE INDEX CONCURRENTLY`, leaving an INVALID index that halts the next `frappe db diff` until it is dropped. The queries that find such rows first are in `site#c-sweettalk-aggregates` and `site#c-sweettalk-richer-values`; for a value's own bound on a column that did not have it, the query is the check's condition negated, `WHERE "<column>" NOT BETWEEN <lo> AND <hi>`, keeping the rows that are NULL, and for a kind's parts `SELECT id FROM <table> WHERE NOT (<sql>)`. A changed hash drops the old check and adds and validates the new one the same way.
11. **A removed aggregate keeps its unique values.** A soft-removed aggregate keeps its row, so a unique value stays reserved until a partial index can exclude it ([#274](https://github.com/caramelizedev/caramel/issues/274)). A partial index (`where:`) is not declared here (`site#c-sweettalk-limits`).

## Reasons

- **The database is the only place a race cannot pass.** A read under a lock is only as safe as the next caller who forgets the lock; a unique index refuses the second writer whatever path it took.
- A `CHECK` holds for every writer. `Rows`, SQL backfills and other services skip SweetTalk's constructors; without it, their bad row fails at its next load, far from the write and as a refusal. A tightened bound stops the migration that validates it ([ADR 0008](../0008-migrations.md)) instead of a later read. A range or a length is evaluated on the written row alone, with no reads, and `database_check: false` serves a table whose writes cannot spare it.
- A state check holds for every writer, as a bound does. Removing a state that rows still hold stops the migration that validates the new check, not a later load. SugarORM compares an expression check by name, hence the hash.
- One nullable group of columns plus one check says "all or none" once. The alternative, an attribute per part with a `never` on each pair, is what the domain repeated by hand, and PostgreSQL could not enforce it.
- A half-set value cannot be built in Crystal, because its type needs every part. The check and the load refusal cover the writes that do not go through Crystal.
- A CHECK for the members `parts:` omits matters as much as one for those it lists: a receipt holds no payee, and the rule that says so is the one most often forgotten.
- **Options on `has`, words for the rest.** One attribute's uniqueness, index or check reads best on its line; what spans attributes or the lifecycle's state needs a line of its own, and `check` always needs SQL.
- **By name, not by column.** `Changeset#unique_constraint` maps by the leading column and prefixes the error with it, which is not a sentence; SweetTalk maps the constraint's own name, which SugarORM derives the same way at compile time and at run time, so a composite index and a check map alike.
- **A sentence is required on `check`.** SQL says nothing a reader can show; `unique` can name its attributes, so it may default.
- **Hash the SQL.** PostgreSQL rewrites a check's text, so SugarORM compares expression checks by name only; a name that carries the SQL's hash makes an edit a replacement.
- **Deletes first.** Writing the new entity before deleting the old one makes a replaced value a duplicate for one statement; deferrable constraints would hide this and every other violation until commit, past the refusal that reloads the aggregate.
- **The sentence belongs to the value.** Every attribute of `Cents` refuses the same way, so `otherwise:` is declared once, on the value, and not again on each `has`.
- Rejected: patterns as `CHECK` constraints. PostgreSQL reads regular expressions differently from Crystal: it refuses `\z`, which `Email` uses, reads `\b` as a backspace and lets `.` match a newline; its `\d`, `\s`, `\w` and `(?i)` follow the database's locale, ASCII-only under Latte's `C`, where Crystal's follow Unicode.
- Rejected: leaving a non-literal bound out of the database unannounced. A reader of the value could not tell which bounds the database holds.
- Rejected: a PostgreSQL enum for the state. `ALTER TYPE` cannot drop a value, and SugarORM already manages `check_…` constraints.
- Rejected: a claims table written in the same transaction. It is the workaround these constraints replace: nothing in the schema says which aggregate it guards. A unit that runs once declares a derived table, which is the claim, named by the unit ([ADR 0046](0046-transactions.md)).
- Rejected: deferrable unique indexes. A violation at commit would surface after the command's rescue, as a raw error, and an upsert cannot target a deferrable index.
- Rejected: a partial unique index for soft-removed rows. It needs `where:` on an index, which SugarORM does not declare yet ([#274](https://github.com/caramelizedev/caramel/issues/274)); the limit is named instead of worked around.
- Rejected: a sentence per attribute for a value's bound. A value's refusal is the value's, shared by every attribute of that type, so the sentence is declared once on the value.
